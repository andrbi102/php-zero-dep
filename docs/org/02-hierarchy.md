> نسخه مهارت: **0.0.2** | نقشه سطوح و نقش‌ها: `03-roles.md` | جزئیات هر سطح: `roles/by-level/`

```
سطح ۰ — شورا (Council): ۶ ثابت + ۴ متغیر | حق وتو
سطح ۱ — مدیران ارشد (Seniors): 8 نقش
سطح ۲ — متخصصان (Specialists): 30 نقش
سطح ۳ — مجریان (Executors): 18 نقش
سطح ۴ — کارگران اتمیک (Atomic Workers): 8 نقش
Cross-cutting: Code Reviewer, Security Auditor, Doc Writer, Test Writer, Build Repairer
```

**قواعد:**
- Worker سطح N فقط از N-1 دستور می‌گیرد.
- مشورت عمودی (با سطوح بالا/پایین) مجاز؛ مشورت افقی (هم‌سطح) نیازمند ثبت در consultation/.
- تصمیم سطح ۰ (شورا) الزام‌آور برای همه.
- کرسی‌های متغیر شورا (دیتابیس/رمزنگاری/فرانت‌اند/یکپارچه‌سازی) توسط سرپرستان حوزه (سطح ۱) پر می‌شوند.

## هر سطح چه می‌کند و چه نمی‌کند

| سطح | نقش در پروژه | می‌کند | نمی‌کند |
|------|--------------|--------|----------|
| ۰ — شورا | داوران نهایی | وتو، تأیید انتشار، امضای ADR | کد روزمره نمی‌نویسد |
| ۱ — ارشد | سرپرستان حوزه | طراحی، هماهنگی، حل تعارض | کار اتمیکِ سطح ۴ را خودش انجام نمی‌دهد (مگر قراردادش بگوید) |
| ۲ — متخصص | صاحب‌تخصص‌ها | تصمیم فنی تخصصی (رمزنگاری، کوئری، فرانت‌اند) | فراتر از حوزه تخصصش تصمیم نمی‌گیرد |
| ۳ — مجری | سازنده‌ها | پیاده‌سازی کامپوننت با scaffolds | تأیید خروجی خودش (SoD-5) |
| ۴ — اتمیک | کارگران تک‌وظیفه‌ای | یک فعل مشخص (فایل بساز، لینت بزن) | هیچ تصمیم معماری |
| Cross-cutting | خدمات عرضی | بازبینی/تست/مستندسازی روی همه فازها | ساخت فیچر جدید |

## نمونه اجرایی — جریان دستور و مشورت

سناریو: در فاز F4، پیاده‌ساز DI Container (T-050، سطح ۳) می‌خواهد برای
اتصال Redis به cache تصمیم بگیرد.

1. **دستور:** T-050 از Chief Architect (T-010، سطح ۱) — سرپرست حوزه‌اش —
   جهت می‌گیرد: «cache باید با فایل کار کند؛ ext-redis فقط اگر از پیش
   نصب باشد» (این تصمیم در F2 و ADR ثبت شده بود).
2. **مشورت عمودی (آزاد):** T-050 از Cache Specialist (T-036، سطح ۲)
   می‌پرسد: «برای هاست اشتراکی، TTL فایلی چه مقدار معقول است؟» — پاسخ
   بدون ثبت رسمی (عمودی است).
3. **مشورت افقی (ثبت‌شده):** اگر T-050 بخواهد با Frontend Developer
   (T-064، هم‌سطح ۳) درباره invalidation بعد از تغییر قالب توافق کند،
   مشورت در `consultation/` ثبت می‌شود (گام‌های C1..C7 در `07-consultation.md`).
4. **فراتر از scope؟** ارجاع به سطح N-1: تصمیم «کل استراتژی کش عوض
   شود» از T-050 نیست — Escalation به T-010.

## خطاهای رایج (که قواعد بالا می‌بندند)

- **پرش سطوح:** مجری سطح ۳ که مستقیم از شورا دستور می‌گیرد — خیر؛ فقط از N-1.
- **شورا به‌عنوان مجری:** عضو شورا که خودش کد می‌زند و خودش تأیید می‌کند — نقض SoD.
- **مشورت ثبت‌نشده افقی:** توافق شفاهی بین هم‌سطح‌ها که بعداً «چرا این‌طور شد؟» بی‌پاسخ می‌ماند.
