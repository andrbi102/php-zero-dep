یک فعل، یک خروجی، یک مالک، یک DoD.

## چرا مدل سازمانی؟

خروجی PHP بدون فرایند، بدهی فنی می‌شود: کد بازبینی‌نشده، انتشار بی‌امضا،
تصمیم معماری بی‌ADR. این مدل هر گام را به یک مسئول با DoD گره می‌زند —
هم‌راستا با چرخه «plan → test → implement → review → verify → remember → improve»
(SPEC بخش ۱۵، ECC).
